# Variant independence audit

Starting commit: `c585f8c5f38705a7efa79bf05148a8c6989b142a` (the fetched `origin/main` used to create `astra/variant-independence`). All file:line evidence and links refer to this commit.

## Result

68 families, 95 named axes and 268 named values are covered. 18 families have no named axes and are still included. All 47 CSS files and 174 source files in the recorded inventory were scanned.

186 values are independent; 68 have conditional child/part dependencies; 14 have intentional CSS combinations and no recorded child dependency. These mutually exclusive totals count value rows, not distinct defects. See [matrix.json](./matrix.json) → `counts` and `families`.

28 expanded selector branches combine positive manifest choices (including booleans/element modifiers); 0 require two named sibling values on the same axis. All named values have a standalone selector or documented base behavior. The combined rules are intentional contrast/layout adjustments, not proof that one sibling variant needs another. The retained component can nevertheless depend on another family's public values through composition. Evidence is in `combinedRules` and the per-value `css` objects.

23 families have 110 direct child-axis dependency records, including forwarded choices, current child defaults and optional branches. Records are per call site/axis, not unique bugs; transitive consequences can be followed through the target family. A depends-on status means a supported branch can request those values, not that every render requires every value.

## Scope and interpretation

- The required matrix is `families → axes → values`. Each value includes a status, source evidence, CSS rule IDs, React evidence, demo/spec findings and dependency IDs. Axis defaults include the CSS-only outcome and the allowed-values-only outcome.
- Independence is about omitting another value. Shared base CSS/tokens remain necessary. Empty default marker rules (Calendar square/month, Switch short, Chip filter) do not depend on a sibling value; deleting their base rules would be a different operation.
- Positive `:is()` alternatives are split; selector commas mean OR. Negated classes are not prerequisites. At-rules and responsive conditions are preserved. `declarationsOnlyInCombinedRules` lists exact property/value pairs seen only in intersections; per-value `propertiesAuthoredOnlyInCombinationForThisValue` also catches context-only paint/geometry. Neither field means the whole value is unavailable alone.
- CSS-only omission notes are source-level cascade consequences with exact base/removed rule IDs. No browser rendering of pruned builds was performed. Runtime state, caller content, theming and conditional rules can change computed pixels.
- Demos are examples, not allowed-combination schemas. `demoCompositions` indexes 379 explicit combinations; wrapper/default-only occurrences are reported as not found where appropriate. Specs are historical records; manifest and current implementation define the audited inventory.
- Manifest booleans, states and element modifiers are retained as evidence for intersections. The DONE denominator is the named `variants` axes; this is not an exhaustive independent status list for every runtime state or composition prop.

## Reviewed React, gallery and spec combinations

### resolved-default-behavior

Alert chooses its live-region role from the raw tone prop before the helper fills a default; changing the manifest default to danger would not update that role automatically. Overlay surface classes use manifest defaults while anchored wrappers use their own side defaults (Popover bottom, Tooltip top); placement is also expressed by runtime data-side.

Proposed fix: Resolve each generated default once before both behavior and class construction, and keep actual overlay placement authoritative after collision handling.
