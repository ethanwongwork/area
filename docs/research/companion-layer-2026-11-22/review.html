Area as a layer beside every tool

Area keeps what your product looks like, and why, in one place you own. It hands that to every tool that makes things for you, and shows you in pictures what those tools did with it.

Screens are still coded and drawn in the tools people already use. Area sits beside them as its own window. Nothing in the app has changed yet: this page asks the decisions, with my recommendation shown as the default for each.

Five jobs

Capture

Point Area at what you have. It drafts a system and asks you to confirm it as choices.

Keep

System, brand, references and explorations, versioned, with every pick kept.

Connect

One button per tool. Area writes its setup, tests it, and shows which tools read what.

See

Each tool's changes as before and after, with off-system values flagged. No terminal.

Teach

Picks become written taste rules, then a judge, then, later and only if you choose, a model of your own.

Where the gap is

Every generator and design tool now takes a design system, but each keeps it inside its own product, so a brand gets rebuilt in every tool and drifts. No one joins the three layers, and no one holds them in a form the owner keeps.

Held by design-system platforms

System

Tokens, components, docs. Served to agents over MCP, mostly at enterprise prices and with call quotas.

Held by brand platforms

Brand

Logos, assets, guideline text. No code tokens; one large platform forbids using its brand kits outside its own app.

Held by nobody

Taste

References, explorations, picks with pictures and the reasons. Lost in chats and comments today.

Agents also still drift with an MCP server connected. What works is files they read (AGENTS.md, skills) plus a check they can run on their own work. Area already has a generator, area check and a read-only MCP server.

Three window sizes

The full window, as the app is today. A narrow panel that stays on top beside your editor or design app. A quick find on a global shortcut: search tokens, colors, icons, logos and components, then copy or drag.

Picks happen where you work

An agent can ask a question that shows as a card inside Claude, Cursor or another host that draws MCP Apps. The answer goes to Area's taste log with both options rendered.

Plain words

Cards say "changed", "kept" and "sent back", never "commit" or "diff". The code is one click away for engineers.

Setup in five minutes

Start from a website, a repo, a design file or images. Confirm the draft as choices. Turn on the tools Area found on this Mac. Send one test prompt and watch it come back.

Simplifying today's app

The app has four things: Systems (now with Brand and Explorations), References, Connections and Activity. Since Nov 10 it has been growing into a coding environment, with its own agent, line diffs, a file editor and a terminal. The layer gives that up: people build in their tools, and Area is what those tools read from and report to.

From picks to a model of your own

The value is in the log of picks, and only if it is recorded right: both options rendered at true size, the question, the version, strength, "both bad", and a training flag that is off by default.

Stage 0 · now

Log

One event per pick on every surface, kept beside the system.

No model yet. Picks without both options rendered can't train anything.

Stage 1 · weeks

Taste rules + judge

Written rules you approve. A judge shown about 8 of your similar past picks.

About 60% agreement on close calls in current research. Ranks and flags; never decides.

Stage 2 · ~500 picks

Scorer, then adapters

A small per-person scorer, then a LoRA on an open model, on a Mac or hosted.

Gains over stage 1 unproven for design systems; goes stale with each version.

Stage 3 · later

Brand model

Drafts screens and imagery in the brand without a long prompt.

Research-grade. Still sits on top of stage 1, not in place of it.

Hosted fine-tuning is closing: one major provider stopped taking new organisations in May 2026. Open weights are where adapters live now, which fits building on open-source models.
