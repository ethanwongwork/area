# Date field and picker implementation survey

**Question:** How do shadcn, Radix, React Aria, Base UI, Primer, Fluent 2, Carbon, Ant, MUI and Spectrum build date fields, single pickers and range pickers, and what should Area reuse from its Calendar?

**Answer:**
- The clearest segmented-field compositions are React Aria, Spectrum 2 and MUI X; shadcn supplies recipes, while Fluent compat, Carbon and Ant primarily use text-input pickers.
- Radix and Base UI have no public date primitives in the pinned catalogs. Primer's picker is internal; source-level geometry was not accessible.
- Reuse Area's existing Calendar modes and overlay boundary. Keep segmented entry, date parsing and range-field semantics separate from calendar painting.
- Source values below are pinned declarations or explicitly labeled derivations, not browser measurements. Dependency baselines and Carbon's preview are distinguished.
- The evidence supports a future DateField/DateRangePicker proposal; it does not approve or implement either family.

## 1. shadcn

**Coverage and anatomy.** No independent segmented DateField in the reviewed recipes. The basic DatePicker is Label → Popover → outline Button (formatted date or placeholder) → PopoverContent → Calendar. The input alternative is an editable InputGroup with calendar trigger; it parses with `new Date(e.target.value)`, so it is not equivalent to locale-aware editable segments. DateRangePicker is the same recipe with one summary Button and a range Calendar. ## Proposals

1. **Recommended: keep Calendar as the rendering and navigation owner.** A future DateField should own localized segments, partial values, validation and form submission; DatePicker/DateRangePicker should own field-to-calendar value synchronization, popup focus and commit/cancel.
