# Evidence: state, optics and motion

Checked **2026-10-09**. Area `origin/main` is `6f896789a5200bcbd34fe87de458e60ca82141d6` (A). Research inputs are at `2097df6d80ef9a0ca6a7f7e6f4db946e6749db01` (R). Public documents below are dated evidence; a URL without a commit does not claim immutability. No state values were inferred from screenshots.

## Apple

- [Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons?changes=latest_1), checked 2026-10-09: custom buttons need a press appearance; system button styles supply interaction states and accessibility adaptation. **Area implication:** provide immediate press feedback even when a material is simplified. This is not a prescribed shadow displacement or opacity.
- [Toggles](https://developer.apple.com/design/human-interface-guidelines/toggles?changes=l_1) and [Focus and selection](https://developer.apple.com/design/human-interface-guidelines/focus-and-selection/), checked 2026-10-09: toggle appearance can change the background; selection may use a changed symbol shape, while focus identifies the input target. **Area implication:** persistent selection and transient focus need distinct signals. Apple does not establish Area's seven-state renderer or a uniform cross-platform effect table.
- [Build a SwiftUI app with the new design, WWDC25](https://developer.apple.com/videos/play/wwdc2025/323/), “App structure” and “Liquid Glass effects”, checked 2026-10-09: interactive glass can scale, bounce and shimmer; presented interfaces can emerge from their source controls. **Area implication:** material response can reinforce interaction, but Area's no-bounce/no-default-press-scale rules deliberately constrain this translation. No claim of native Liquid Glass fidelity or adoption of Apple's motion constants.
- [Motion](https://developer.apple.com/design/human-interface-guidelines/motion?changes=l_9_3), checked 2026-10-09: feedback should be brief, interruptible and restrained for frequent interactions; Liquid Glass motion differs by input method. **Area implication:** don't add a light sweep or elastic event to every hover.
- [Accessibility, motion guidance](https://developer.apple.com/design/human-interface-guidelines/accessibility?changes=lat_6&language=objc), checked 2026-10-09: Reduce Motion removes/reduces repetitive and spatial effects, with fades as alternatives and avoidance of animated blur. **Area implication:** retain the final state while removing optional optics motion. Area currently chooses zero-duration changes, not Apple's optional fade alternative.

## Fluent

- [Fluent 2 Button](https://fluent2.microsoft.design/components/web/react/core/button/usage), “Behavior” and “Accessibility”, checked 2026-10-09: ToggleButton has persistent checked state; visible indicator changes should communicate state/action. Guidance requires text/icon contrast across interactive states and separately treats disabled buttons. **Area implication:** a hover glint cannot replace the checked mark. Disabled is a semantic inability to act, not a low-opacity loading animation.
- **Pinned implementation:** [Fluent UI React Button source](https://github.com/microsoft/fluentui/blob/8abb0781d7d8bdb5e7bccaad16a6e4ba7efaf1aa/packages/react-components/react-button/library/src/components/Button/useButtonStyles.styles.ts#L40-L79), checked 2026-10-09. Hover/press select separate background, border **and foreground** tokens; color transitions are explicit and reduced-motion duration is `0.01ms`. [Focus](https://github.com/microsoft/fluentui/blob/8abb0781d7d8bdb5e7bccaad16a6e4ba7efaf1aa/packages/react-components/react-button/library/src/components/Button/useButtonStyles.styles.ts#L103-L123) is separately drawn. [Disabled styles](https://github.com/microsoft/fluentui/blob/8abb0781d7d8bdb5e7bccaad16a6e4ba7efaf1aa/packages/react-components/react-button/library/src/components/Button/useButtonStyles.styles.ts#L322-L368) neutralize hover/press paint. Token names alone do not prove different resolved foreground values in every Fluent theme. **Area implication:** borrow separation of state slots and focus, but retain Area's fixed hover ink and zero reduced-motion durations.
- [Fluent 2 Motion](https://fluent2.microsoft.design/motion), “Duration and easing” and “Transitions”, checked 2026-10-09: movement communicates changes and relationships, with timing appropriate to size/travel; enter/exit and elevation are distinct transitions. **Area implication:** a small material response must not dictate how a whole dialog opens. Use Area's existing role-specific timing.
- [Fluent Accessibility](https://fluent2.microsoft.design/accessibility), “Keyboard navigation and assistive technologies”, checked 2026-10-09: focus must remain perceivable and managed when temporary interfaces close. **Area implication:** closing a glass menu does not remove focus restoration or allow its trigger's decorative halo to masquerade as focus.

- [Fluent Field](https://fluent2.microsoft.design/components/web/react/core/field/usage), “Validation” and “Disabled fields”, checked 2026-10-09: error can change the border and add a validation message/icon; disabling the form component leaves its label, help and validation text enabled. **Area implication:** do not apply material disabled opacity to explanatory content outside the unavailable control.

## Material 3

The following public pages were read in the rendered browser on 2026-10-09; the web text fetch returned only their JavaScript shell.

- [States overview](https://m3.material.io/foundations/interaction/states/overview): states can combine, including selected plus hover. This does not mean every state gets a cumulatively darkening overlay.
- [State layers](https://m3.material.io/foundations/interaction/states/state-layers): a translucent state layer sits between the container and content, uses the content's on-color, and only one such layer is applied at a time. The page currently lists hover 8%, focus 10%, press 10%, drag 16%. These are **M3 source values, not Area recommendations**; do not substitute remembered older values or apply them blindly over glass/gradients.
- [Applying states](https://m3.material.io/foundations/interaction/states/applying-states): hover uses a low-emphasis fade; web keyboard focus has a ring-like indicator; press uses a ripple and can have elevation treatment; disabled suppresses interaction feedback and reduces color/elevation. Selected/focus/press can coexist. **Area implication:** separate persistent semantic state, transient paint and keyboard focus, but retain Area's immediate hover-in and omit a new ripple by default. The page's ordinary disabled behavior is not a blanket requirement to remove a deliberately focusable `aria-disabled` control from navigation.

- [Text field guidelines](https://m3.material.io/components/text-fields/guidelines), “Error text” and “Error icon”, checked 2026-10-09 in the rendered browser: error guidance should explain recovery, and a second visual signal such as an error icon supplements color. **Area implication:** a danger-tinted rim alone is not the whole invalid-state treatment.

**Not found:** a universal M3 reduced-motion duration or a seven-state material-specific shader recipe in these pages or the focused site search for reduced motion. The Area fallback in this report comes from its motion policy, not an invented M3 constant. M3's examples also do not establish how every Area family should expose open or invalid state; those remain component semantics. Apple/Fluent/M3 are precedents for particular mechanisms, not citations proving each authored style recipe below.

## Area: state semantics and paint

No material proposal closes that gap without testing.
- [Button hover/press/open](https://github.com/ethanwongwork/area/blob/6f896789a5200bcbd34fe87de458e60ca82141d6/packages/styles/src/components/button.css#L135-L153): hover changes body/border; press changes body; an expanded menu trigger retains the active plate unless selected. This is a specific menu-trigger contract, not all openable controls.
- [Button immediate state/focus/disabled/loading](https://github.com/ethanwongwork/area/blob/6f896789a5200bcbd34fe87de458e60ca82141d6/packages/styles/src/components/button.css#L155-L183): no default press scale, outline focus, disabled opacity, loading preserves ink/focus. [Fixed foreground declaration](https://github.com/ethanwongwork/area/blob/6f896789a5200bcbd34fe87de458e60ca82141d6/packages/styles/src/components/button.css#L11-L17).
- [Input focus and invalid](https://github.com/ethanwongwork/area/blob/6f896789a5200bcbd34fe87de458e60ca82141d6/packages/styles/src/components/input.css#L80-L98): invalid owns the border, focus outline and halo tone; [disabled/read-only/loading](https://github.com/ethanwongwork/area/blob/6f896789a5200bcbd34fe87de458e60ca82141d6/packages/styles/src/components/input.css#L116-L134) stay distinct, with only the status glyph taking validation tone. Do not tint the editable text red through a material filter.
- [Switch checked/hover/press/focus](https://github.com/ethanwongwork/area/blob/6f896789a5200bcbd34fe87de458e60ca82141d6/packages/styles/src/components/switch.css#L123-L137): checked position and color survive; press has an existing 2px thumb stretch. [Disabled/read-only/loading](https://github.com/ethanwongwork/area/blob/6f896789a5200bcbd34fe87de458e60ca82141d6/packages/styles/src/components/switch.css#L139-L157) preserves on/off information and uses the shared duration controls. This component-specific stretch is not permission to scale all material controls.
- [Forced-color requirements](https://github.com/ethanwongwork/area/blob/6f896789a5200bcbd34fe87de458e60ca82141d6/packages/styles/src/forced-colors.css#L1-L65): system focus, invalid dashed edge and real selected/check marks remain when authored shadow/fill disappears.
- [Surface casts/width](https://github.com/ethanwongwork/area/blob/6f896789a5200bcbd34fe87de458e60ca82141d6/packages/tokens/src/axes/surface.ts#L15-L81), [role elevation](https://github.com/ethanwongwork/area/blob/6f896789a5200bcbd34fe87de458e60ca82141d6/docs/DESIGN_SYSTEM.md#L156-L165), [near-black policy](https://github.com/ethanwongwork/area/blob/6f896789a5200bcbd34fe87de458e60ca82141d6/docs/DESIGN_SYSTEM.md#L272-L278). Material must not make ordinary inflow controls float on hover or resurrect dark Card halos.
