# Material axis and emission contract — proposal

## Ownership and preset structure

`id: "material"`, label Material, `defaultPreset: "none"`, attribute `data-area-material`, presets **none, glass, tactile, soft**. This follows D2/D4; it does not bring back Paper/Aero/Glow/Prism as launch materials. [REVIEW.md:124–132](https://github.com/ethanwongwork/area/blob/0169fb7b6d85a910a24a684f9b5b3b537a735956/docs/research/astra/materials/REVIEW.md#L124-L132).

Material owns three prefixes: `--area-material-gate-`, `--area-material-input-`, `--area-material-role-`. Base derivation alone writes `--area-material-paint-`; presets and React never write that derived prefix. Surface adds `--area-surface-part-` and exact `--area-shadow-tooltip:` / `--area-shadow-toolbar:` claims. The theme's `--area-shadow-color` remains theme-owned: **do not broaden Surface to `--area-shadow-`**. Type's `--area-text-`/`--area-display-` are also already taken. [color.ts:104–137](https://github.com/ethanwongwork/area/blob/4ea50618cf19e8737b607c9f983f64dd310d921d/packages/tokens/src/axes/color.ts#L104-L137), [type-size.ts:73–83](https://github.com/ethanwongwork/area/blob/4ea50618cf19e8737b607c9f983f64dd310d921d/packages/tokens/src/axes/type-size.ts#L73-L83), [surface.ts:21–26](https://github.com/ethanwongwork/area/blob/4ea50618cf19e8737b607c9f983f64dd310d921d/packages/tokens/src/axes/surface.ts#L21-L26).

[namespace-audit.json](namespace-audit.json) lists **all ten actual registered axes** and their expanded namespaces. `build.mjs` imports the immutable registry and passes Material plus the Surface namespace extension to its real integrity checker. It also confirms a broad shadow-prefix collision is rejected. Every preset writes the same complete keys, so a Glass child clears inherited Tactile/Soft values. Pills and legacy ui are not extra axes. [registry.ts:21–32](https://github.com/ethanwongwork/area/blob/4ea50618cf19e8737b607c9f983f64dd310d921d/packages/tokens/src/axes/registry.ts#L21-L32), [registry.ts:76–115](https://github.com/ethanwongwork/area/blob/4ea50618cf19e8737b607c9f983f64dd310d921d/packages/tokens/src/axes/registry.ts#L76-L115), [THEMING.md:15–33](https://github.com/ethanwongwork/area/blob/4ea50618cf19e8737b607c9f983f64dd310d921d/docs/THEMING.md#L15-L33).

Three mutually exclusive recipe gates are `--area-material-gate-glass`, `-tactile`, `-soft`. None is `(0,0,0)`, Glass `(1,0,0)`, Tactile `(0,1,0)`, Soft `(0,0,1)`. They are discrete: never interpolate them or accept a fractional gate from Theme. Optical strengths are separate continuous inputs. A new per-role multiplier does not control a semantic fill, focus ring, selected mark or text opacity. The action/selection precedent is one inherited 0/1 input with derived colors, not ancestor selectors repainting every descendant. [emphasis.ts:13–29](https://github.com/ethanwongwork/area/blob/4ea50618cf19e8737b607c9f983f64dd310d921d/packages/tokens/src/axes/emphasis.ts#L13-L29), [base.ts:90–108](https://github.com/ethanwongwork/area/blob/4ea50618cf19e8737b607c9f983f64dd310d921d/packages/tokens/src/emit/base.ts#L90-L108).

The proposed numeric map also includes one-hot source/stroke selectors and eight fixed gradient slots. Unused slots have zero alpha; stop count and ordered offsets are validated before emission. Preset maps are theme-invariant. Dark/light color pairs are derived separately, so a theme change cannot change a control's geometry. All color sources are semantic names, never literal preset hexes.

## Numeric zero is not CSS `none`

In [demo.css](demo.css), each receiver re-derives its paint from inherited gate leaves. Each named scope declares **every** recipe gate. The nested child therefore cannot retain a parent's raised-shadow recipe through a higher-specificity ancestor selector. The nested experiment also compares each receiver's computed paint with its isolated scope after removing ancestor preset attributes.

Use a fixed shadow-list slot with its color alpha multiplied by its gate; multiplying blur alone leaves a sharp shadow, and multiplying only offsets leaves the shadow in place. Give every gradient stop an alpha gate; multiplying the gradient angle or stop positions does not remove its fill. Zero-alpha shadows/gradients remain computed list entries but draw nothing in the experiment. That is **paint absence**, not syntax absence.

A filter is different. `brightness(0)` makes ink black; `blur(0)` is a non-none filter and is not a safe identity operation. The checked Chromium changed 50 pixels in light and 57 in dark with `blur(0)` versus `none`. Filter a dedicated optical pseudo/child behind content, gate that layer's opacity, and keep it `pointer-events:none` and out of accessibility. Its content must contain only effect paint, never labels/icons/children. The fixture's zero-opacity filter and backdrop-filter layers match literal removal exactly. See [browser-results.json](browser-results.json). Residual filter computation and stacking still exist; this experiment does **not** prove zero GPU cost or absence of a compositing layer.

Recommendation: numeric gates are the portable paint selector; optional optical nodes may be omitted by a renderer that knows the **resolved** scope. A CSS-only implementation must still render correctly when those nodes exist with opacity zero. Do not require JS merely to select a preset. Do not put filter, backdrop-filter, opacity, isolation, transform or clip changes on an existing content ancestor as the gate: that risks descendants, stacking and nested None. Any new isolation/wrapper in a real component needs task 20's identity proof; the fixture uses identical geometry in both references. Literal `filter:none` remains the off rule for any path that writes a content filter.

## Derivation and scope re-emission

In a future `emit/base.ts`, add `materialDerivations()` to `derivedTokens()`. Input leaves hold angles, lengths, ratios, source switches and per-role strengths. Derived paint holds resolved colors, shadow vectors, gradient stops and optional-layer alphas. In `emit/css.ts`, add Material via AXES and include `[data-area-material-controls]` in re-emission; preserve every existing axis/preference boundary. Recompute actual role paint on the receiver where component tone/state/size slots become known. Never inherit a fully baked receiver recipe from an ancestor.

Current `emitTokens()` emits all defaults at root; `emitAxes()` validates preset output and then re-emits derived values at attributes. `@property` is deliberately leaf-only. Do not register paired colors, shadow strings, gradients, role recipes or derived lengths; no new registrations are needed for the prototype. [css.ts:80–106](https://github.com/ethanwongwork/area/blob/4ea50618cf19e8737b607c9f983f64dd310d921d/packages/tokens/src/emit/css.ts#L80-L106), [css.ts:145–184](https://github.com/ethanwongwork/area/blob/4ea50618cf19e8737b607c9f983f64dd310d921d/packages/tokens/src/emit/css.ts#L145-L184), [base.ts:357–384](https://github.com/ethanwongwork/area/blob/4ea50618cf19e8737b607c9f983f64dd310d921d/packages/tokens/src/emit/base.ts#L357-L384).

Changing only a control value must also recompute: Theme emits a control-boundary marker even when no axis ID changes. For CSS-only consumers, declare the marker with the primitive override. Re-emit at theme, accent, neutral, material, Surface, contrast, type and density boundaries, not only Material boundaries. Receiver-local derivation catches component tone changes that are not Theme axes.

## Decorative color derivation (D5)

Proposed endpoint set: neutral → `fg-default`; accent → `fg-accent`; tone → `fg-<tone>` for info/success/warning/caution/danger/discovery. These are **inputs to decoration**, not permission to assign a new foreground. Example derived base seed: `color-mix(in srgb, var(--area-bg-surface) 92%, var(--area-fg-accent) 8%)`; the percentages are proposal seeds, not measured Area values. A serialized one-hot source selector chooses endpoints with nested `color-mix()` just as action/selection does; the selected endpoint then mixes toward a canonical ground. The data file's source switches are total and validated, so no invalid all-zero source choice reaches CSS.

Generate `--area-material-paint-tint`, `-highlight`, `-shade`, `-glow`, `-stop-1`…`-stop-8` from those endpoints, strengths and current ground. Keep source light/dark pairs until a real color property consumes them. Decorative shadow/rim ink can use the existing neutral ramp and theme-owned `shadow-color`; do not overwrite either. No literal hex palette in Material, no CSS `color`/SVG ink reassignment, and no scaling Action/Selection or invalid/focus paint by material strength. D5 governs **new material decoration**; the pixel-identical Surface migration preserves existing literal colors before any separately approved color change. [REVIEW.md:133](https://github.com/ethanwongwork/area/blob/0169fb7b6d85a910a24a684f9b5b3b537a735956/docs/research/astra/materials/REVIEW.md#L133-L133), [base.ts:143–162](https://github.com/ethanwongwork/area/blob/4ea50618cf19e8737b607c9f983f64dd310d921d/packages/tokens/src/emit/base.ts#L143-L162), [THEMING.md:84–92](https://github.com/ethanwongwork/area/blob/4ea50618cf19e8737b607c9f983f64dd310d921d/docs/THEMING.md#L84-L92).

## Row-plate is a role, not another Button

The thirteen serialized IDs in `model.mjs` normalize task 04's spaces and slashes to hyphens: `floating surface` → `floating-surface`, `raised control` → `raised-control`, `recessed field/track` → `recessed-field-track`, `thumb/knob` → `thumb-knob`, `indicator/fill` → `indicator-fill`; the other names are unchanged. This is a serialization mapping, not a new role taxonomy. [04 role vocabulary](https://github.com/ethanwongwork/area/blob/0169fb7b6d85a910a24a684f9b5b3b537a735956/docs/research/astra/materials/04-role-map/role-map.json#L10-L24). They include **row-plate** for Menu, Nav, Tree, Table, Select, Command palette and Calendar days, per D6. D16 leaves their spacing, geometry and semantic ink intact. [REVIEW.md:134–135](https://github.com/ethanwongwork/area/blob/0169fb7b6d85a910a24a684f9b5b3b537a735956/docs/research/astra/materials/REVIEW.md#L134-L135), [REVIEW.md:153–154](https://github.com/ethanwongwork/area/blob/0169fb7b6d85a910a24a684f9b5b3b537a735956/docs/research/astra/materials/REVIEW.md#L153-L154).

A row adapter identifies the existing plate's paint bounds, rest/hover/focus/selected state and ground. Material may add tint, inset relief or a highlight to that plate; it must preserve selection precedence, connected range bands, virtualized-row geometry, full-width table joins and focus. Table paints cells and flush-side extensions; a new per-cell outer shadow would create seams. Calendar's range band and selected endpoint are distinct semantic paints, not independent embossed buttons. [navigation.css:197–215](https://github.com/ethanwongwork/area/blob/4ea50618cf19e8737b607c9f983f64dd310d921d/packages/styles/src/components/navigation.css#L197-L215), [navigation.css:263–270](https://github.com/ethanwongwork/area/blob/4ea50618cf19e8737b607c9f983f64dd310d921d/packages/styles/src/components/navigation.css#L263-L270), [surface.css:1149–1166](https://github.com/ethanwongwork/area/blob/4ea50618cf19e8737b607c9f983f64dd310d921d/packages/styles/src/components/surface.css#L1149-L1166), [calendar.css:89–121](https://github.com/ethanwongwork/area/blob/4ea50618cf19e8737b607c9f983f64dd310d921d/packages/styles/src/components/calendar.css#L89-L121).

Draft strengths: None 0; Glass .25; Tactile .4; Soft .55. These are adjustable prototype defaults, **not permanent caps**. The multiplier affects added decoration only; a selected row remains selected at strength 0. In dense lists, start without per-row backdrop acquisition; that is a proposed performance default pending D14 measurement, not a prohibition. Keep the whole-row plate within the existing row geometry and reuse the parent's already-acquired glass when appropriate.

## Inner rims (D11, D16)

Use the receiver's actual outer shape, not a new Material radius. For uniform corners the inner curve is `max(var(--area-radius-floor), calc(var(--_material-outer-radius) - var(--_material-rim-inset)))`. The adapter supplies the true radius/inset, counting the existing border once. At Sharp the floor is 0; a square outer radius stays square. An explicit pill override remains a pill even at Sharp: D16 prevents Material from undoing the separate pills setting. For elliptical/per-corner radii apply the inset to each radius pair and the element's existing clipping geometry; do not assume one scalar fits all shapes. Suppress a decorative rim when no physical interior remains rather than changing the component's size.

The current radius axis publishes the minimum/concentric inputs and base derives `radius-floor=min(4px,radius-step)`. Card's existing media radius already floors the subtraction. D11 makes that rule binding for new inner rims. [radius.ts:17–18](https://github.com/ethanwongwork/area/blob/4ea50618cf19e8737b607c9f983f64dd310d921d/packages/tokens/src/axes/radius.ts#L17-L18), [base.ts:328–353](https://github.com/ethanwongwork/area/blob/4ea50618cf19e8737b607c9f983f64dd310d921d/packages/tokens/src/emit/base.ts#L328-L353), [surface.css:79–85](https://github.com/ethanwongwork/area/blob/4ea50618cf19e8737b607c9f983f64dd310d921d/packages/styles/src/components/surface.css#L79-L85), [REVIEW.md:145](https://github.com/ethanwongwork/area/blob/0169fb7b6d85a910a24a684f9b5b3b537a735956/docs/research/astra/materials/REVIEW.md#L145-L145).

## Text effects are an explicit instance opt-in

Propose `materialEffect="none" | "engraved" | "embossed" | "glow"` **only** for display Text and Button's label slot; default none. Do not add a Theme switch that decorates all labels or SVGs. The adapter paints an extra shadow/highlight around unchanged ink and type, only on the opted-in text node. It never filters the Button ancestor or changes glyph strokes. Reject/no-op with a development warning on ordinary body/small text; changing to Material None suppresses the extra effect even if the instance prop remains. No duotone or gradient-ink API in this launch proposal. [REVIEW.md:147–154](https://github.com/ethanwongwork/area/blob/0169fb7b6d85a910a24a684f9b5b3b537a735956/docs/research/astra/materials/REVIEW.md#L147-L154).

Opt-in is not a contrast waiver. A button label may be small, so its effect must pass worst-case paint/focus checks at its real size and be removed under the relevant preference fallback. D13 permits the opt-in; D16 still owns the ink/type boundary. Fallback must retain native text rather than replacing it with pseudo text or hiding it with transparent fill.
