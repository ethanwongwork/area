All conclusions below come from pinned source. “Inference” means tracing declarations/control flow, not a verified cross-browser outcome. The local demo supports F01, but pixels are not the source of its values.

## F01 — An unpositioned close button makes a panel-sized ring

**Defect, source-derived and reproduced locally.** The shared ring selector includes `.ogui-overlay__header > button`; its `::after` is absolute with inset zero and inherits the button's radius. The base close button has width 2rem, aspect ratio 1 and radius 50%, but no positioning. The liquid close rule adds fill/shadow/transition, also no positioning. The positioned ancestor is the overlay surface. Consequently the circular close ring is laid out against the panel, producing an ellipse across it instead of a ring around the close control. [packages/recipes/src/liquid.source.css:179–227](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/recipes/src/liquid.source.css#L179-L227) [packages/recipes/src/styles.css:1099–1118](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/recipes/src/styles.css#L1099-L1118) [packages/recipes/src/styles.css:1153–1171](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/recipes/src/styles.css#L1153-L1171) [packages/recipes/src/liquid.source.css:965–973](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/recipes/src/liquid.source.css#L965-L973)

## F02 — Sparse presets and local derivation are not reset semantics

**Contract limitation / inference.** Nested `theme.glass='liquid'` emits no look tokens, so it keeps ancestor look values in CSS; it does not restore default glass. A parent mode-specific tint can also defeat a child generic tint: the fill checks `tint-dark`/`tint-light` before `tint`. Example: parent smoked preset + child generic red still resolves the parent's mode-specific tint for a surface. [packages/core/src/look.ts:65–83](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/core/src/look.ts#L65-L83) [packages/core/src/look.ts:99–118](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/core/src/look.ts#L99-L118) [packages/core/src/look.ts:138–155](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/core/src/look.ts#L138-L155) [packages/recipes/src/liquid.source.css:85–96](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/recipes/src/liquid.source.css#L85-L96) [packages/recipes/src/liquid.source.css:148–159](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/recipes/src/liquid.source.css#L148-L159)

## F03 — Portals can lose the effective inherited look

**Control-flow defect / inference; counterexample not browser-executed here.** Parent Theme emits blur=4. A nested Theme emits only rim=0 and its own palette. In-flow descendants inherit blur=4; the nested React context's token record contains only that provider's emitted look fields, not the parent blur. Menu/Popover copies those tokens into a body portal, so its blur falls back to 1. Dialog/Drawer and ToastProvider copy the same kind of record. Normal explicitly complete provider look values are copied correctly. ## F04 — The classic-scope guard is finite, not a nearest-ancestor resolver

**Selector inference.** The generated guard excludes a node under classic unless it is also under any `classic liquid` ancestor chain. In `liquid → classic → liquid → classic → Button`, the last Button satisfies both historical chains, so the inner exemption admits liquid paint although its nearest design is classic. The generator uses that guard on the first compound after its liquid scope. It does not inspect the nearest boundary. This counterexample follows directly from the selector; it was not rendered as a custom fixture. [scripts/generate-liquid-css.mjs:21–23](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/scripts/generate-liquid-css.mjs#L21-L23) [scripts/generate-liquid-css.mjs:43–66](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/scripts/generate-liquid-css.mjs#L43-L66)

**Proposed fix:** test alternation deeper than a single classic island and a single liquid re-entry, or use a scope/receiver scheme whose matching boundary is explicit. Do not take a stylesheet comment promising nearest scope as implementation proof.

## F07 — Contrast is a palette check, not a composited-glass guarantee

**Concrete counterexample from source arithmetic.** `readableForeground` chooses whichever of `#101214` and `#f9f8f3` has the higher ratio, without a minimum-ratio repair. `createGlassTheme('dark', {accent:'#777777'})` therefore selects `#f9f8f3` with `accentContrast = 4.211349069950931`, below the 4.5 threshold used by the source's own tests. This is calculated by the pinned luminance implementation and was reproduced from the built core module; it is not an image estimate. [packages/core/src/theme.ts:149–181](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/core/src/theme.ts#L149-L181) [packages/core/src/theme.ts:189–205](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/core/src/theme.ts#L189-L205) [packages/core/src/theme.ts:240–241](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/core/src/theme.ts#L240-L241) [packages/core/src/theme.test.ts:20–27](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/core/src/theme.test.ts#L20-L27)

Even passing that palette pair would not qualify a glass button: primary paint includes a white-mixed gradient, a translucent stop, pointer glint and a whole-element hover filter.
