# Exactly what Area adds or does differently

“Area current” below pins `origin/main` at the snapshot. “Area proposed” pins this research series at its input commit; none of its new material-axis/control names should be mistaken for shipping APIs. OpenGlass is an implemented library with real native React behavior; the Area material layer is still a design and specimen exercise.

## 1. Layer breadth and explicit receivers

**OpenGlass current:** a glass-focused sparse Look over classic/liquid design, with selectors that specialize controls/wells/sheets. No role map or per-role control field appears in GlassLook. [packages/core/src/look.ts:8–83](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/core/src/look.ts#L8-L83) [packages/recipes/src/liquid.source.css:303–328](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/recipes/src/liquid.source.css#L303-L328) [packages/recipes/src/liquid.source.css:810–821](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/recipes/src/liquid.source.css#L810-L821) [packages/recipes/src/liquid.source.css:1069–1100](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/recipes/src/liquid.source.css#L1069-L1100)

**Area proposed addition:** twenty-five taxonomy entries include materials, primitives and visual languages; not twenty-five mutually exclusive shipping presets. Those counts describe research coverage, not parity with OpenGlass's forty API components or a recounted latest-main census. [docs/research/astra/materials/01-taxonomy/README.md:1–19](https://github.com/ethanwongwork/area/blob/ce84e32725f4e9321c77b4a75eb142a1c565674c/docs/research/astra/materials/01-taxonomy/README.md#L1-L19) [docs/research/astra/materials/04-role-map/README.md:22–59](https://github.com/ethanwongwork/area/blob/ce84e32725f4e9321c77b4a75eb142a1c565674c/docs/research/astra/materials/04-role-map/README.md#L22-L59) [docs/research/astra/materials/07-controls/controls.md:7–16](https://github.com/ethanwongwork/area/blob/ce84e32725f4e9321c77b4a75eb142a1c565674c/docs/research/astra/materials/07-controls/controls.md#L7-L16)

## 2. Independent Surface ownership

**OpenGlass current:** ordinary liquid controls own their own multi-lobe lift; shadow scales selected alpha values, not a separate elevation policy. The angle aims bloom/rim while cast offsets remain fixed. [packages/recipes/src/liquid.source.css:64–75](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/recipes/src/liquid.source.css#L64-L75) [packages/recipes/src/liquid.source.css:303–319](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/recipes/src/liquid.source.css#L303-L319) [packages/core/src/look.ts:35–36](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/core/src/look.ts#L35-L36)

**Area current:** Surface owns decorative border width and named shadow tokens; Flat emits none. In-flow controls/fields have no cast, thumbs have their allowed lift, Card and floating shells use distinct roles. [packages/tokens/src/axes/surface.ts:15–53](https://github.com/ethanwongwork/area/blob/eaa9222ebf98f7c260f9e0dd448940523003d4d3/packages/tokens/src/axes/surface.ts#L15-L53) [docs/DESIGN_SYSTEM.md:156–165](https://github.com/ethanwongwork/area/blob/eaa9222ebf98f7c260f9e0dd448940523003d4d3/docs/DESIGN_SYSTEM.md#L156-L165)

**Area proposed difference:** Material is a separate optical axis; Surface remains the single cast owner. Derived `--area-paint-*` outputs combine inputs at receivers, with independent cast gains/geometry and relief intent. A zero-blur shadow ring is an edge, not a cast lobe to be softened. This needs actual emitter/API changes; it is not present because the report names it. [docs/research/astra/materials/07-controls/architecture.md:5–27](https://github.com/ethanwongwork/area/blob/ce84e32725f4e9321c77b4a75eb142a1c565674c/docs/research/astra/materials/07-controls/architecture.md#L5-L27) [docs/research/astra/materials/07-controls/controls.md:24–45](https://github.com/ethanwongwork/area/blob/ce84e32725f4e9321c77b4a75eb142a1c565674c/docs/research/astra/materials/07-controls/controls.md#L24-L45) [docs/research/astra/materials/07-controls/architecture.md:95–113](https://github.com/ethanwongwork/area/blob/ce84e32725f4e9321c77b4a75eb142a1c565674c/docs/research/astra/materials/07-controls/architecture.md#L95-L113)

**Area proposed addition:** None/Trace/Quiet/Full are ordinal channel permissions, never a scalar multiplying opacity or blur. Context/semantics narrow the style-role cell. ## 7. Where Area is not ahead yet

OpenGlass implements forty interactive React recipes, CSS material fallback, optional SDF maps and media-backed WebGL. Area task 16 is a static compiled-CSS specimen for selected presets/families with documented omissions; it is not a shipped material runtime or a replacement for those interaction contracts. Task 15 already found contradictions between Area's inheritance proposal and complete preset records, and between presets and role lobe budgets. Those must be resolved before claiming stronger implementation consistency. [packages/recipes/src/index.tsx:264–421](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/recipes/src/index.tsx#L264-L421) [packages/recipes/src/atlas.tsx:575–746](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/recipes/src/atlas.tsx#L575-L746) [packages/react/src/filters.tsx:56–136](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/react/src/filters.tsx#L56-L136) [packages/react/src/webgl-surface.tsx:14–32](https://github.com/moekoelueker/open-glass-ui/blob/4943bbfd5611fe211cccf4b50c384345468d635b/packages/react/src/webgl-surface.tsx#L14-L32) [docs/research/astra/materials/16-specimen/README.md:1–20](https://github.com/ethanwongwork/area/blob/ce84e32725f4e9321c77b4a75eb142a1c565674c/docs/research/astra/materials/16-specimen/README.md#L1-L20) [docs/research/astra/materials/16-specimen/limitations.md:20–36](https://github.com/ethanwongwork/area/blob/ce84e32725f4e9321c77b4a75eb142a1c565674c/docs/research/astra/materials/16-specimen/limitations.md#L20-L36) [docs/research/astra/materials/15-consistency/findings.md:5–43](https://github.com/ethanwongwork/area/blob/ce84e32725f4e9321c77b4a75eb142a1c565674c/docs/research/astra/materials/15-consistency/findings.md#L5-L43)

**Recommendation:** retain OpenGlass's strongest ideas—shared input variables, specialized recipes, quiet nested rows, explicit fallback paths and native component semantics—then implement and test Area's receiver/cap/ownership contracts before adding broader presets. The novelty claim should be “broader, explicitly constrained material composition,” not “the first global adjustable material system.”
