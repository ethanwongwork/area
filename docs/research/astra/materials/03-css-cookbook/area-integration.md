## Recommended implementation boundary

Retain task 01's option of **new optical inputs beside Surface**, with Surface continuing to own its namespace. Body transmission, backdrop treatment, reflection, texture and emission could have separate inputs; any cross-axis output belongs in `emit/base.ts`. Exact public names and scalar ranges remain task 07 work. Do not insert an unreviewed `--area-material-*` namespace merely to make a demo look integrated.

For a future floating glass Popover or Calendar surface, read its existing surface/foreground, role radius and `shadow-float`; derive body alpha and decorative reflection privately. Keep normal content and required state indicators outside masked/filtered decoration. For a Button, read its existing action or tone slots instead of a generic accent. For a recessed Input or Slider track, describe intrinsic inset relief separately from any Surface cast shadow. Family-specific absorption is task 04/05; these examples are proposals only.

The demo pages define **no public Area tokens**. They read `--area-bg-surface`, `--area-fg-default`, `--area-fg-accent`, `--area-edge-control`, `--area-shadow-color` and `--area-shadow-card` when supplied, with local `--demo-*` fallbacks. `--_tint`, `--_glass`, `--_shade` and `--_relative` are unregistered local derivations. Every `.demo-scope` and `.specimen` declares them again. This demonstrates scope mechanics; it does not load the production stylesheet, enforce every component role, or validate Area's contrast maps.

The cast-shell demo also avoids a real composition hazard: a Surface token may be `none`. Consuming it as the wrapper's entire `box-shadow` lets Flat work, while a child can draw permitted intrinsic inset modeling. Concatenating it with another shadow would form invalid `none, ...`. An intrinsic **external** relief lobe would still bypass Flat's elevation promise even on a child; this wrapper pattern does not authorize that.

## Adoption checks, not completed implementation work

Before accepting a recipe into Area: establish measured values in the relevant spec; define its role/part/state mapping; check the emitted root and nested axis scopes; exercise theme switches using Area's current restyle behavior; verify actual painted contrast over adverse backdrops; preserve forced-colour focus/identification; compare the geometry against the existing corner setting; and run the checks appropriate to any later production changes. None of those production changes are made here. Browser demo observations are recorded separately in [verification.md](verification.md).
