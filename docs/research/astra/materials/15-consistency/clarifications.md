These eight items have two pinned sides and a recommended authority, but are **not counted as confirmed contradictions**. A plausible compatible reading exists; the missing detail must be supplied before implementing a compiler or claiming a complete schema.

## A01 — Raised-control budget does not name local relief or an emissive halo

07 permits local relief on sparse raised controls; 13 requests it for Soft/Tactile and a halo for Glow. 11 allows zero new cast lobes and “at most one static reflection/gradient and one ring,” without explicitly naming an inset-relief or emission allowance. An inset is not a cast, and emission is not reflection. [07-controls/controls.md:76–78](https://github.com/ethanwongwork/area/blob/b0768c8d809946b82d6b00139ecc33fe4e57f528/docs/research/astra/materials/07-controls/controls.md#L76-L78) [13-presets/model.py:20–23](https://github.com/ethanwongwork/area/blob/b0768c8d809946b82d6b00139ecc33fe4e57f528/docs/research/astra/materials/13-presets/model.py#L20-L23) [13-presets/model.py:67–82](https://github.com/ethanwongwork/area/blob/b0768c8d809946b82d6b00139ecc33fe4e57f528/docs/research/astra/materials/13-presets/model.py#L67-L82) [11-performance/budgets.md:9–16](https://github.com/ethanwongwork/area/blob/b0768c8d809946b82d6b00139ecc33fe4e57f528/docs/research/astra/materials/11-performance/budgets.md#L9-L16)

**Recommended winner:** Treat 11's named allowance as conservative until the budget explicitly includes/excludes these channels. Do not assert that its zero-*cast* rule by itself bans every inset; that would overstate the text. The resolution needs an explicit per-role channel budget, not a change to Button's no-cast contract.

## A02 — One inset treatment versus two lobes

11 defines total shadow counts by lobes, yet allows a recess “at most one static inset treatment.” 13 models one concave treatment using two opposed inset lobes. [11-performance/budgets.md:9–17](https://github.com/ethanwongwork/area/blob/b0768c8d809946b82d6b00139ecc33fe4e57f528/docs/research/astra/materials/11-performance/budgets.md#L9-L17) [13-presets/contract.md:39–39](https://github.com/ethanwongwork/area/blob/b0768c8d809946b82d6b00139ecc33fe4e57f528/docs/research/astra/materials/13-presets/contract.md#L39-L39) [13-presets/model.py:65–66](https://github.com/ethanwongwork/area/blob/b0768c8d809946b82d6b00139ecc33fe4e57f528/docs/research/astra/materials/13-presets/model.py#L65-L66)

**Recommended winner:** 11 owns the budget unit, but must say whether “treatment” means a pair or one primitive. Until reviewed, use a plain well rather than declaring the paired recipe accepted. C02/C03 have explicit numerical lobe caps; this row does not, which is why this is an ambiguity rather than another proven overrun.

## A06 — Layer-model arrays versus the compact control record

01 defines `content.decoration[]`, `body.paints[]`, `edges[]`, `reflection[]`, `shading.*[]` and other ordered channels. 07 deliberately provides a compact authoring interface. 13 emits `content.decoration: "none"`, scalar relief/gloss, and named gradients. These can be equivalent representations, but no general codec proves that equivalence for multiple layers or non-none content treatment. [01-taxonomy/layer-model.md:27–40](https://github.com/ethanwongwork/area/blob/b0768c8d809946b82d6b00139ecc33fe4e57f528/docs/research/astra/materials/01-taxonomy/layer-model.md#L27-L40) [07-controls/controls.md:20–48](https://github.com/ethanwongwork/area/blob/b0768c8d809946b82d6b00139ecc33fe4e57f528/docs/research/astra/materials/07-controls/controls.md#L20-L48) [13-presets/model.py:7–15](https://github.com/ethanwongwork/area/blob/b0768c8d809946b82d6b00139ecc33fe4e57f528/docs/research/astra/materials/13-presets/model.py#L7-L15)

**Recommended winner:** 01 owns layer meaning; 07 owns typed user controls; 13 is a restricted recipe encoding. Specify a versioned expansion/normalization mapping (for example, string `none` becomes an empty decoration array) rather than accepting all representations as the same wire schema. Task 14 stores the recipe snapshot; it does not implement this general material compiler. [14-tooling/build.py:18–24](https://github.com/ethanwongwork/area/blob/b0768c8d809946b82d6b00139ecc33fe4e57f528/docs/research/astra/materials/14-tooling/build.py#L18-L24)

## A07 — Patch paths and reset semantics are not a complete export schema

07 proposes owner-separated Material/Surface patches, recursive named-record merge, null reset and role presence. 14's sample wraps both modes and uses `patch.light.roles.<role>.gloss`, whereas its embedded snapshot stores `modes.light.roles.<role>.controls.gloss`; it embeds Surface controls inside the role snapshot. This is a viable transport design if a codec maps owners and paths, but it is not the same path contract. [07-controls/architecture.md:147–185](https://github.com/ethanwongwork/area/blob/b0768c8d809946b82d6b00139ecc33fe4e57f528/docs/research/astra/materials/07-controls/architecture.md#L147-L185) [14-tooling/build.py:18–25](https://github.com/ethanwongwork/area/blob/b0768c8d809946b82d6b00139ecc33fe4e57f528/docs/research/astra/materials/14-tooling/build.py#L18-L25) [13-presets/model.py:14–15](https://github.com/ethanwongwork/area/blob/b0768c8d809946b82d6b00139ecc33fe4e57f528/docs/research/astra/materials/13-presets/model.py#L14-L15) [13-presets/model.py:98–99](https://github.com/ethanwongwork/area/blob/b0768c8d809946b82d6b00139ecc33fe4e57f528/docs/research/astra/materials/13-presets/model.py#L98-L99)

State the path translation, scope/mode selection, owner dispatch, missing/null/zero behavior and version migration. Storage nesting does not change token ownership. A content hash and JSON round trip do not demonstrate patch application. 14's checker verifies hashes/value preservation but never applies this material patch. [14-tooling/build.py:84–107](https://github.com/ethanwongwork/area/blob/b0768c8d809946b82d6b00139ecc33fe4e57f528/docs/research/astra/materials/14-tooling/build.py#L84-L107)

## A08 — A published control has no complete rendering interpretation

07 exposes gloss softness; 13 gives Soft/Aero nonzero `gloss.softnessPx`, but its gloss interpretation specifies a white-to-transparent envelope, extent, orientation and mask without defining how softness changes that envelope or which primitive consumes it. 14 promises the same live softness control. [07-controls/controls.md:45–45](https://github.com/ethanwongwork/area/blob/b0768c8d809946b82d6b00139ecc33fe4e57f528/docs/research/astra/materials/07-controls/controls.md#L45-L45) [13-presets/model.py:67–77](https://github.com/ethanwongwork/area/blob/b0768c8d809946b82d6b00139ecc33fe4e57f528/docs/research/astra/materials/13-presets/model.py#L67-L77) [13-presets/contract.md:43–43](https://github.com/ethanwongwork/area/blob/b0768c8d809946b82d6b00139ecc33fe4e57f528/docs/research/astra/materials/13-presets/contract.md#L43-L43) [14-tooling/builder.md:29–29](https://github.com/ethanwongwork/area/blob/b0768c8d809946b82d6b00139ecc33fe4e57f528/docs/research/astra/materials/14-tooling/builder.md#L29-L29)

**Recommended winner:** Preserve 07's distinct softness meaning. Before calling the record render-complete, define its primitive, units, clipping and scaling; alternatively mark that control unsupported in this recipe and report the loss. Do not invent a root `filter: blur()` or equate softness with strength. C04 already rejects softened thumb cues under 11; this ambiguity also matters on otherwise eligible shells.
