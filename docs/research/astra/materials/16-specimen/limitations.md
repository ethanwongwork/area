# Requested recipe → effective specimen

The exact Paper, Glass and Tactile records are retained in `preset-data.js`. The renderer does **not** claim literal fidelity to every request. This ledger distinguishes guarded reduction, implementation approximation and untested behavior. Source pins for every contract below are in [evidence.md](evidence.md); actual receiver decisions are in [verification.json](verification.json).

## Per-family result

- **Button solid:** Paper leaves native paint; Glass adds only its Trace edge; Tactile has paired local inset relief, gloss and a rim inside the existing box. No preset adds a cast. The lab clips relief/gloss to measured free space between the shell and label, capped at an authored 4px perimeter. Default and compact use their actual heights for task 13's density equation. Raised-control relief is the unresolved task-11 interpretation noted below.
- **Button ghost:** all three retain the transparent native button and existing hover/focus paint. Tactile's generic raised-control recipe is intentionally suppressed by the ghost guard. On the image stage only, a separate opaque host protects the label; it is not a resting button fill. Ghost buttons inside opaque reading islands need no extra host.
- **Input:** Paper stays native; Glass and Tactile retain their Trace concave relief. The field value and focus/invalid paint stay native. Relief is restricted to measured shell-to-control clearance, without changing height or padding. No field transmission or independent blur is allowed, including after slider edits.
- **Switch:** the track gets the recessed recipe and the handle gets the thumb recipe; selected fill and travel remain Area's. The thumb is limited to its existing shadow plus one plain/gradient rim: Glass gloss and Tactile relief/gloss/double-rim are reduced. Track relief is clipped to an authored 1px inner band. The external label has a separate opaque ground on the image stage.
- **Segmented:** the track gets recessed relief. The selected item gets the reduced thumb recipe; idle items retain their native clear bodies. Selection changes update the binding, ARIA and roving tab stop. The track's small native padding bounds its local treatment. The same Glass/Tactile thumb omissions apply.
- **Card:** Paper remains opaque with its rim. Glass acquires the scene once around an opaque reading island. Tactile **drops its two inset lobes in light mode** because Area's Card already consumes the two-lobe container budget; it retains them in dark mode, where the native Card halo contributes no visible lobes. Tactile rim/gloss remain clipped. This is the task-15 C02 conflict resolved toward task 11.
- **Menu:** Paper keeps the native body/cast; Glass uses one acquisition and a reading island; Tactile **drops relief** to retain the native two-lobe float cast. Rows do not get independent optical layers. Tactile's proposed divider engraving is **not rendered**: the existing thin separator remains native because the lab has no separately validated two-line allocation.
- **Popover:** same floating-shell reduction as Menu. The inline fixture has no trigger, portal, collision positioning or arrow, so continuation of the glass/rim into an arrow is **not demonstrated**. Its ghost action remains native inside the reading area.
- **Dialog:** same floating-shell reduction. This is an inline, labelled nonmodal region containing Area Dialog anatomy, not an open modal. Scrim, top-layer integration, focus trap/return and nested portal scopes are **not demonstrated**. No modal behavior or scrim material is fabricated.
- **Toast:** same floating-shell reduction. The fixture turns off the live announcement and omits Toaster entry/exit/stack behavior; its content uses native paint. This is a surface specimen, not a notification system test.
- **Table:** every preset resolves to an opaque reading plane with native header/row/stripe/rule paint. Glass transmission and Tactile container modeling are suppressed. The lab also omits optional shell rims: the real wrapper has no verified free perimeter. No per-row material.
- **Code block:** every preset keeps the existing opaque code ground, typography and code layout. All added container treatment is suppressed; no verified spare shell perimeter is present. No grain, blur or glow crosses code. This small snippet is not a syntax-color or long-code stress test.

## Cross-cutting approximations and omissions

**Border allocation is approximate for all three presets.** Task 13 allocates the existing decorative width to the requested edge. This lab retains the native border and draws an additional masked rim immediately inside it, because replacing the source border indiscriminately could erase required control/state paint. Double-rim splits that interior band; it does not prove that native and material edges have become one owner. Radius follows the used outer radius and inset radius for this fixed radius setting. Sharp/pill/squircle contours and fractional-raster quality were not tested. A production binding must identify decorative versus required edges explicitly.

**Trace is structural.** The field/track recipe keeps one signed light/shade pair, dropping other channels. Task 13 calls that pair one treatment; task 11 also speaks of lobe totals. The lab retains the pair on fields/tracks as a proposed interpretation, not a settled performance allowance. It likewise allows local relief on eligible solid buttons even though task 11 does not expressly name it in that row. Thumb and floating conflicts are reduced instead: no extra thumb gloss/relief and no float inset lobes. See task 15 C03/C04 and its raised-control/inset clarifications.

**Masks are conservative authored approximations.** Sparse shell reading islands use existing padding; relief/gloss/grain use a clipped perimeter. They preserve layout, but are not general content-exclusion paths for arbitrary nested components. The demo has one blur owner per illustrated shell; it does not implement a general nested-owner compiler. Backdrop acquisition still samples the receiver's full box even where an opaque reading island hides it. Glass Card is an experimental exception to task 11's default no-container-blur rule, not an approved exception. Full composed contrast and whole-scene backdrop bounds remain unverified, so these Glass previews cannot be treated as production-approved recipes. “Plain fallback” removes the experiment.

**Role coverage is deliberately finite.** Active optical bindings are container, floating-surface, raised-control, recessed-field-track and thumb-knob. Text, glyphs and semantic fills remain native None. Page remains native; the image is a separate fixture scene. Edges alias their shell rather than painting a second independent role. Dividers stay native as above; no scrim is instantiated. The editor retains all twelve role names so patches can be exported, but a role without a bound receiver has no visible effect here.

**The 07 editor is a bounded implementation.** It provides the requested lighting, depth, shadow softness/spread/strength, glow strength/source, two gradient stops and angle, stroke modes/opacity, fill transparency, blur, grain and gloss, with per-role edits. It is not the advanced named-layer editor: no adding/removing stop arrays, radial/conic/mesh backend, custom edge mask, lens/refraction, inner/both glow placement, environment reflection, arbitrary source casts, absorption escalation or body-gradient editing. None of the three source defaults requests these backends. Only the fixed Outlined cast recipes are adapted. The glow color is explicitly the same in both modes; gradient colors expose both modes. Positive gloss softness is recorded as suppressed, because task 13 supplies no concrete equation for it. Glow is allowed only on a sparse container with remaining budget; other controls can legitimately have no visible result under guards.

**Patch resolution is a local proposal.** Complete 13 role record → edited global leaves → edited role leaves → guards. This makes 07's global controls usable despite task 15 C01. It does not silently change 07/13. The lab normalizes finite slider inputs and clamps stop movement to preserve order; it does not implement task 07's full import validator or reject/repair UI. Reload clears patches; draft download is an archival export only, with no import/shareable URL or production Theme prop.

**State coverage is partial.** Area keeps native body/focus/selection paint. Local optical layers add no animation; Button press reverses relief and drops gloss. Focus-within conservatively removes gloss/glow and makes transmitting shells opaque, even when focus did not originate from the keyboard. Invalid/disabled guards remove decoration, but this fixture does not exercise all invalid/loading/read-only combinations. It does not claim native modal/menu overlay behavior from a static SSR page.

**Fallback coverage is partial.** Unsupported mask/backdrop features and reduced-transparency/greater-contrast/forced-color preferences have no-effect/opaque rules. The manual fallback was executed. Native OS preference execution, Safari, Firefox, forced-colors, screen reader, touch, extreme zoom, full contrast across worst-case photographs and performance profiling of this page were not run. User-edited extremes are exploratory and unvalidated. No safe blur/depth threshold or WCAG conformance is inferred from a slider range or token-test pass.
