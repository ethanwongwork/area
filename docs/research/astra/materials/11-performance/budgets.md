# Proposed material budgets by role

**Unreviewed policy, not an implementation or a measured device-independent limit.** Apply these caps after task 05’s None/Trace/Quiet/Full absorption and family guards. A material choice never grants more elevation than the current Surface/context contract. A passing synthetic case does not grant permission to put its recipe on every component.

Area’s current contract already reserves elevation: in-flow controls/fields have no cast shadow; thumbs use `shadow-1`, docked Panel `shadow-2`, Card its special halo, and floating shells `shadow-float`. Flat removes Surface shadows, dark Card removes its halo. Toolbar has a documented special recipe. These are existing facts, not recommendations from timing. [Design-system elevation](https://github.com/ethanwongwork/area/blob/6f896789a5200bcbd34fe87de458e60ca82141d6/docs/DESIGN_SYSTEM.md#L156-L165), [Surface definitions](https://github.com/ethanwongwork/area/blob/6f896789a5200bcbd34fe87de458e60ca82141d6/packages/tokens/src/axes/surface.ts#L15-L81), [Toolbar](https://github.com/ethanwongwork/area/blob/6f896789a5200bcbd34fe87de458e60ca82141d6/packages/styles/src/components/toolbar.css#L27-L35).

## Default caps

Numbers in this table are **proposed review starting points**. “0 blur” means no `backdrop-filter` on that part, not `blur(0px)`. Shadow counts include cast lobes, inset relief and decorative blurred glows in one total, but never remove required focus/selection paint to meet a cosmetic cap. Existing documented exceptions are reviewed individually, not silently rewritten. Grain means a shared static image, not one live filter per instance. A “ring” is a decorative paint layer; it does not replace a required boundary.

| Role | Backdrop/filter budget | Shadow, edge and texture budget | Animation budget and fallback |
| --- | --- | --- | --- |
| page | 0 backdrop blur; 0 live displacement | No cast shadows; at most one static grain plane and one authored background gradient for the scene | No continuous material animation. Static color/gradient or opaque ground |
| container | 0 independent blur by default; an explicitly reviewed glass shell may become the single owner for its group | At most two permitted Surface/relief lobes, one static grain plane shared by descendants, one decorative edge | Keep paint static while content scrolls. Replace texture/optics with a solid body first |
| floating surface | One backdrop owner per open overlay group; start evaluation at ≤12px, with radius constant through transitions; no child re-blur; 0 live displacement | Existing two-lobe `shadow-float`; one ring, one optional static tile. Tooltip/Toolbar remain their documented exceptions | Existing shell transform/opacity only, then verify with real content; opaque body is the fallback. Large sheets require a separate area test |
| raised control | 0 blur; 0 refraction on normal controls or list options | 0 new cast lobes in-flow; at most one static reflection/gradient and one ring on eligible non-dense controls; no per-row grain | Immediate semantic state paint; no continuous pulse, moving gradient or animated blur. Flat plate in dense lists |
| recessed field/track | 0 blur; 0 displacement | At most one static inset treatment if separately accepted; no added cast; no grain in reading/editing wells | Keep depth paint static while value/selection changes; solid well/rail fallback |
| thumb/knob | 0 independent blur or displacement by default | Existing single `shadow-1` plus at most one nonblurred highlight/rim; no live grain | Move the existing handle using its component contract; leave optical parameters constant. Plain opaque handle fallback |
| indicator/fill | 0 blur or filters on data/selection/progress pixels | 0 new blurred glows by default; optional one small static halo only for an explicitly decorative indicator, separate from its opaque semantic core | Only semantic progress/loading motion already allowed by the component; no material-driven shimmer. Core stays in every fallback |
| divider | 0 blur/filter | 0 blurred lobes; at most a two-line unblurred engraved pair where allowed; one ordinary line in dense content | Static. Required division survives simplification |
| edge | 0 blur/refraction | One solid or decorative gradient ring; prefer double background for an opaque body, mask only where a separate ring is necessary; no stacked animated masks | Do not animate angle continuously. A solid required edge/focus outline is independent and immediate |
| glyph | 0 material filter on intrinsic content or small functional symbols | 0 decorative blur/glow on ordinary UI glyphs; rare display inscriptions require their own task 12 evidence | Native semantic mark motion only; preserve crisp ink and intrinsic pixels |
| text | 0 material filter | 0 shadows/glows/grain on dense UI text, code, placeholders or editable values; display text exceptions are outside this budget | Keep foreground fixed on hover; no animated text relief. Plain semantic ink |
| scrim | 0 independent blur by default; do not duplicate a dialog’s backdrop filter | One alpha fill; 0 texture, shadows or gradient-ring layers | Existing scrim opacity transition; immediate endpoint under reduced motion. Opaque/stronger ground when contrast requires it |

The ≤12px floating-surface starting point is **not a discovered safe threshold** and must not be used as a media-query hardware heuristic. The tested lenses are only 96×52px each. Real menus/sheets can have much larger sampling regions, different backdrop roots, clipping and overlap. Review the actual shell and viewport before accepting even one blur. The useful enforceable defaults are **zero on repeated rows** and **one optical owner for a group**; radius is a tunable, separately measured parameter.

## Family and nesting consequences

- **Table, TreeView, List options, Menu rows, Command results and Calendar days:** no independent blur, displaced artwork, live grain or extra per-row shadows. Repeated rows consume the shared shell’s material at Trace/None. Selection, hover, focus and range continuity stay explicit. Total DOM count still affects style invalidation; virtualization is an application decision and was not added here.
- **CodeBlock, Message and editable content:** keep a stable opaque reading plane; material stays on an eligible outer shell. Removing expensive decoration must not replace semantic syntax, invalid paint or code backgrounds with a lower-contrast translucent surface.
- **Slider/SliderRange, Switch and Segmented:** the value fill is data, not a moving material gradient. Move the existing thumb and leave blur/displacement off. A fast rAF trace would not justify distorting the scale or losing the fixed mark geometry. [Slider value-fill ownership](https://github.com/ethanwongwork/area/blob/6f896789a5200bcbd34fe87de458e60ca82141d6/packages/styles/src/components/slider.css#L4-L11), [track/mark geometry](https://github.com/ethanwongwork/area/blob/6f896789a5200bcbd34fe87de458e60ca82141d6/packages/styles/src/components/slider.css#L18-L64).
- **Glass in glass:** let the outer owner acquire the backdrop; children use tint/rim paint on that result. A genuinely separate top-layer overlay can own a new surface, but cannot inherit a “free” budget. Test the resulting overlap; this benchmark used non-overlapping panes.
- **Recessed in raised:** the field’s concavity can be a static local inset; do not add a filter to recompute its parent’s material. Shared grain belongs to the parent surface, not to every child pseudo-element.

These follow the pinned [task 04 role inventory](https://github.com/ethanwongwork/area/blob/c3d6664e56570e1fbf4ef530ccc172934806127c/docs/research/astra/materials/04-role-map/README.md#L23-L44) and task 05’s [context guards](https://github.com/ethanwongwork/area/blob/c3d6664e56570e1fbf4ef530ccc172934806127c/docs/research/astra/materials/05-absorption/family-exceptions.md) and [nesting policy](https://github.com/ethanwongwork/area/blob/c3d6664e56570e1fbf4ef530ccc172934806127c/docs/research/astra/materials/05-absorption/policy.md). The role budget constrains recipes; it does not replace their anatomy or classify layout-only wrappers as painted surfaces.

## Release gate proposal

**Option A — conservative structural caps, recommended:** use the table, keep costly paint static and demand a separate real-component benchmark for any exception. Effects can be customized within those reviewed contexts. The downside is less dramatic glass/jelly behavior before device coverage expands; the advantage is predictable suppression on dense content and no runtime guessing from a single browser API.

**Option B — adaptive runtime quality:** sample cadence and disable decoration on slow sessions. This may recover on weak devices, but can respond to unrelated load, change appearance during interaction, and confuse accessibility fallbacks with performance choices. rAF alone cannot tell which paint layer caused a stall. Do not add this mechanism until transition behavior, hysteresis and privacy-safe local sampling are designed and measured. No such detector is implemented here.

For a proposed 60Hz release target, review p95 against 16.67ms; for a 120Hz target review against 8.33ms. These are arithmetic frame periods, **not an allotment for material paint alone**. As an initial gate, require the effect-on scenario’s paired p95 to stay within one calibrated interval and its slow-interval proxy to worsen by less than one percentage point versus effect-off, across three runs on each agreed minimum device. If the baseline itself misses the target, investigate rather than granting a waiver. These thresholds are authored policy options, not vendor recommendations or validated sufficient conditions. Add native scroll and actual pointer/keyboard interactions, production content, multiple overlapping overlays and long-duration power/thermal runs; inspect paint/compositor traces when results diverge.

Prefer transform/opacity for permitted state transitions, but do not assume a blurred transformed surface becomes free: verify its actual paint/compositing behavior. Avoid blanket `will-change`; layer promotion carries its own costs. [Chrome team animation guidance](https://web.dev/articles/animations-guide#avoid_properties_that_trigger_layout_or_paint), checked 2026-10-09. Area already specifies immediate hover/press entry and focus, controlled leave transitions and shell transforms; the stress fixture’s endless optical animation is **not a proposed Area interaction**. [MOTION recipes](https://github.com/ethanwongwork/area/blob/6f896789a5200bcbd34fe87de458e60ca82141d6/docs/MOTION.md#L40-L64), [reduced motion](https://github.com/ethanwongwork/area/blob/6f896789a5200bcbd34fe87de458e60ca82141d6/docs/MOTION.md#L85-L90).

Fallback order: remove live filter animation → replace live grain/refraction with static texture or plain fill → consolidate blur ownership → remove optional blur and decorative glows → retain opaque body and required ink/edge/state paint. Never achieve a timing target by hiding focus, changing hover foreground, weakening text/indicator contrast, disabling keyboard behavior or suppressing a meaningful progress signal. [Area contrast/state contract](https://github.com/ethanwongwork/area/blob/6f896789a5200bcbd34fe87de458e60ca82141d6/docs/CONTRAST.md#L7-L64). Reduced-motion, forced-colors and reduced-transparency fallbacks take precedence regardless of measured speed.
