# Document editor

Checked 2026-09-28. [Method, status meanings and priorities](README.md).

These are proposed Area recipes informed by the cited public examples and guidance. Anatomy is the proposed reading order; variations are candidates to offer, not a claim that every source implements them. Responsive behavior is an Area recommendation unless a source observation explicitly says otherwise. No dimensions are inferred from images.

Component availability is pinned to `18b86465d542f620d532fee351c4f28d50c8ac3a`. `recipe` means reusable packaging is absent but the baseline is composable; `partial` and `missing` identify additional shared behavior or adapters. Native headings, paragraphs, links, lists, forms and layout CSS remain valid building blocks.

## Rich document editor

**Purpose.** Author structured content with discoverable formatting and document status.

**Anatomy, in order (proposal).**

1. Document title and save state
2. Formatting commands
3. Editable document body
4. Selection-specific controls
5. Comments or document outline
6. Status and sharing

**What Area lacks for this baseline.** Rich-text editor integration; FloatingFormatBar. Existing controls cover only the reuses listed above.

**Common variations to catalogue.**

- Persistent toolbar.
- Selection toolbar.
- Page canvas with outline.

**Responsive proposal.** Prioritize the document and essential formatting; disclose remaining commands and show comments in a separate view. General layout basis: [Fluent — Layout](https://fluent2.microsoft.design/layout).

**Behavior boundary.** Document schema, undo, composition input, selection and collaboration require an editor engine. Toolbar and Textarea do not provide rich-text behavior.

**Source observations.**

- [Carbon — Text toolbar](https://carbondesignsystem.com/patterns/text-toolbar-pattern/) (guidance; checked 2026-09-28). Formatting commands can be grouped into text toolbars; this guidance does not supply a document editing engine.
- [Untitled UI — Text editors](https://www.untitledui.com/react/components/text-editors) (public-examples; checked 2026-09-28). Text-editing controls and examples are a reference for a formatted document surface, not evidence of an Area editing engine.
- [Material — Canonical layouts (official Android guidance)](https://developer.android.com/develop/ui/compose/layouts/adaptive/canonical-layouts) (platform-guidance; checked 2026-09-28). Material-derived list-detail, feed and supporting-pane layouts preserve state as panes change visibility; editor tools and document comments are supporting-pane examples.

**What Area lacks for this baseline.** No additional primitive or adapter is identified. Any recipe entries above still need composition and application state; this is not a shipped screen.

**Common variations to catalogue.**

- Tabbed edit and preview.
- Side-by-side view.
- Source-only with preview on demand.

**Extra requirements for expanded variants.**

- Code editor integration — **missing**. No syntax-aware editing engine found. CodeBlock is display and Textarea is native text entry. [range cross-check](https://github.com/ethanwongwork/area/blob/7435813c947188664c665dc59f5fa0ffc5de4e8c/docs/research/library-range/code-editor.md#L29).
- General Splitter — **partial**. Panel already has keyboard/pointer resizing. A general coordinated multi-pane splitter is not found; do not rebuild Panel resizing. [range cross-check](https://github.com/ethanwongwork/area/blob/7435813c947188664c665dc59f5fa0ffc5de4e8c/docs/research/library-range/splitter.md#L98).

**Responsive proposal.** Prefer one active mode on narrow screens; preserve draft and selection when switching back to edit. General layout basis: [Fluent — Layout](https://fluent2.microsoft.design/layout).

**Behavior boundary.** The basic recipe uses Textarea and a fixture preview. Parsing and safe rendering are app work; syntax-aware editing requires a CodeEditor adapter. An exact public Markdown screen was not found in these guidance pages.

**Source observations.**

- [Carbon — Text toolbar](https://carbondesignsystem.com/patterns/text-toolbar-pattern/) (guidance; checked 2026-09-28). Formatting commands can be grouped into text toolbars; this guidance does not supply a document editing engine.
- [Primer — Layout](https://primer.style/product/getting-started/foundations/layout/) (guidance; checked 2026-09-28). Defines header, content, supporting panes and footer; narrow list-detail views can become separate pages, auxiliary panes can become sheets, and summaries can stack.
