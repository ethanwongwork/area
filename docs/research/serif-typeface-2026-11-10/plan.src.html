A screen serif between Georgia Pro and Serrif

Both references were read from the installed font files, node by node. They turn out to be two takes on one model: a Scotch-derived serif with a large x-height, bracketed serifs and ball terminals. Georgia Pro is the sturdy, compact one built for coarse screens. Serrif is the lighter, wider, sharper one built for layout. The plan is an original design that keeps Georgia's sturdiness and fit, takes Serrif's openness and variable structure, and sets its own proportions for 12–16 px interface text.

Licences decide the method. Georgia Pro's licence and Serrif's (a trial copy, whose embedded terms forbid modifying or reassembling the font data) both rule out starting from their outlines. Nothing here imports, traces or converts either font. The references are measured and looked at; every outline of the new face is drawn fresh from numeric targets. In the US a typeface design is not protected but font software is; in the EU a typeface can be a registered design, so the new face must not be a look-alike of Serrif, which is recent. The targets below differ from both on purpose.

The design in one paragraph

A transitional text serif with a vertical axis, moderate contrast and firm, short, bracketed serifs. Lowercase is wide enough to keep counters open but fitted like Georgia. Capitals are a little narrow and a little short so that labels in title case do not shout. Terminals are teardrops rather than full balls at text size, so a c f r y keep their identity without clotting. Every pair that an interface can confuse is drawn apart by default. Bold is usable in a button, not only in a headline. The italic is a true italic kept calm.

Outline nodes

  • Sources are cubic. A node sits on every horizontal and vertical extreme and nowhere else on a curve, with handles exactly horizontal or vertical. Handles never cross and never pass the corner they aim at.
  • The only inflection nodes are on the spines of s S 2 5 8 § $ &, placed at the true inflection.
  • Stems, bowls, serifs and terminals stay as separate overlapping contours. Overlaps are kept in the variable font and flagged for the rasterizer.
  • Every master has the same contours, the same node count, the same node order and the same start node (lowest, then leftmost). Outer contours run counter-clockwise.
  • All coordinates are integers on a 1000 grid. Stems and serif heights are the same integer everywhere they appear.
  • Node budgets, cubic: l 12, i 16, o 8, n 22, h 24, m 34, e 13, c 14, a 26, s 16, g 34, H 28, O 8, R 26, S 16. A glyph over budget is redrawn, not patched.

Anchors for marks

  • Every base letter carries top and bottom; letters that need them carry ogonek, center (strokes), topright (the apostrophe-shaped caron of ď ľ ť) and horn. Marks carry the matching _top, _bottom, _ogonek and their own top for stacking.
  • top sits at exactly the x-height on lowercase and the cap height on capitals, at the optical center: the bounding-box center for symmetric letters, the stem for i j l, the bowl center for a, shifted right on f and left on r by eye.
  • bottom sits on the baseline at the same x. ogonek sits where the last stroke lands (right foot of a A u U, center of e E i I).
  • Ligatures carry numbered anchors per component and caret positions, so marks and the text cursor work inside them.
  • Capital marks are a flatter .case set, 45 above the cap height, so Å and É stay under 940.
  • Accented letters are components plus anchors, never redrawn outlines. Georgia Pro's 447 hand-placed composites are the thing to avoid.

Spacing, kerning and line metrics

  • Spacing is designed, not derived. Tracy's method: fix n and o by eye in nnonoo, H and O in HHOHOO, then give every other letter the sidebearing of the standard whose side it shares (left of b from n, right of b from o). Starting values: n 34 and 28 beyond the serifs, o 38 each side, H 46, O 40.
  • Text fit is slightly open. At opsz 12 the lowercase carries about 4% more sidebearing than Georgia; the Display master takes it back.
  • Kerning follows spacing. One left and one right class per glyph, accents inheriting from their base. Around 60 hand-set model pairs per master (T V W Y A with lowercase, quotes, punctuation after r f y), then the rest by class. Tabular figures and math are not kerned. No pair moves more than 40% of a glyph's width.
  • Line box. Ascender 950, descender −250, line gap 0, the same in all three metric sets, with the typographic-metrics flag on. Ascender minus cap height equals the descender (250), so capitals are exactly centered in the default line and a label centers in a button without nudging. Default line height 1.2.
  • Exact cap and x-height in the font tables, because CSS text-box-trim reads them to trim text to the capitals.
  • Pixel fit. x-height 500 gives 6, 7 and 8 px at 12, 14 and 16 px. At 13 px it is 6.5 px; that half pixel is the one compromise, taken because 13 px is where Area's own interface was measured and the alternative (538) is too large for a serif.
  • No hinting. Current renderers ignore horizontal hints, macOS ignores all of them, and Google's own guidance is to ship variable fonts unhinted. A gasp table asks for symmetric smoothing at every size.

How it gets built

  • Sources: UFO masters and a designspace file in typefaces/area-serif/, at 1000 units per em, written by Python scripts. Each glyph is a small function that places kit parts from the master's values, followed by explicit hand corrections. This guarantees compatible masters and makes a value change (a stem, a serif) reach every glyph at once.
  • Build: fontmake to a variable TrueType font (AreaSerif[opsz,wght].ttf, later AreaSerif-Italic[opsz,wght].ttf) and WOFF2. Cubic sources convert to quadratic at build.
  • Checks on every build: fontTools' interpolation checker, fontspector (universal and Google Fonts profiles), shaperglot for language support, and a script that re-measures the built font against the targets table on this page.
  • Proofs: an HTML proof page per step: control strings, the confusable pairs, real interface strings at 11–16 px at 1× and 2× in light and dark, next to the interface sans and next to both references; then paragraphs at 15–18 px and headlines at 32–64 px.
  • In Area: the built font joins the typeface library in Typography as a system choice, which is where it is finally judged.

Where the risk is. The numbers, structure and engineering can be exact. The quality of the curves is judged by eye from rendered proofs, and that judgment is yours at every phase. Phase 1 is deliberately small so a wrong character costs little.
