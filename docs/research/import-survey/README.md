## Findings and method

The first import boundary should retain token graphs, source locations, theme scopes and component contracts. Static files are useful early inputs, but generated tokens, style functions and preview providers are part of the system that must remain linked. The rankings below are measured from the cells in matrix.json; importer order, record design and hard cases are proposals inferred from those observations.

All 16 systems named in the request are included. The three products are OpenStatus, Documenso and Midday; their scope cells cite explicit shadcn adoption evidence. Primer Primitives is a separately pinned supporting repository for Primer’s token definitions and is excluded from system counts. Its checked version is not asserted to be the exact dependency version installed by Primer React.

Every survey cell cites a file and line in an immutable Git revision. Clones are under `.cache/sources/<id>@<sha>/`; they are shallow/sparse clones, and the validator reads pinned Git blobs and complete tracked-file lists, not mutable worktree contents. No surveyed repository code or build scripts were executed. Component counts are scoped inventories with executable selection rules and complete member paths in matrix.json. They count different kinds of records (families, modules, documented pages or registered elements), so totals are not interchangeable measures of product breadth.

“Not found” is bounded by the named source paths and searches. The Storybook search examines the entire pinned tracked tree for `*.story.*`, `*.stories.*` and `.storybook/` paths; absence does not rule out unpublished stories or a differently named harness. Base UI’s docs-only theme is not counted as a prescribed token format. EUI’s declared per-file license choices are retained as such; including a requested repository does not assert that every file has one permissive license.

## Findings at a glance

- CSS custom properties appear in 15/16 library styling approaches; TS/JS objects appear in 10/16 token cells. Start with static CSS and structured/object token discovery. Evidence: the ranked styling and token tables below.
- Storybook CSF appears in 8/16 libraries. Preview import also needs custom TSX examples, templates and Lit stories. Evidence: the ranked stories table.
- All three sampled products keep local cva-based UI modules, while their theme initialization differs. Preserve the local source and application theme dependencies. Evidence: [OpenStatus](#openstatus), [Documenso](#documenso), [Midday](#midday).

## Proposed importer order

1. **CSS custom-property tokens and scope rules.** Extract declarations, aliases, fallbacks, selectors, layers, media/supports conditions and source order. Preserve unresolved calc/color values and theme scopes; do not flatten all definitions into one map. Evidence: [Radix Themes](#radix) (tokens), [Mantine](#mantine) (tokens), [OpenStatus](#openstatus) (tokens).

2. **Structured token input: JSON/JSON5, DTCG extensions and Style Dictionary lineage.** Recognize $type/$value as well as legacy value objects, aliases and composite values. Preserve vendor extensions and generated/source relationships. Handle Carbon’s per-theme extension and Primer’s JSON5 before claiming generic DTCG coverage. Evidence: [Primer React](#primer) (tokens), [Carbon](#carbon) (tokens), [Gestalt](#gestalt) (tokens), [Atlassian public packages](#atlassian) (tokens).

3. **Restricted TS/JS token objects and Tailwind theme adapters.** Read literal objects, imports, spreads and simple aliases statically. Add Tailwind config and CSS @theme mappings. Keep factory/derivative functions as executable dependencies with unresolved outputs instead of evaluating arbitrary repository code during discovery. Evidence: [Fluent UI React v9](#fluent) (tokens), [Chakra UI](#chakra) (tokens), [Ant Design](#antd) (tokens), [shadcn/ui registry](#shadcn) (tokens), [Midday](#midday) (tokens).

4. **Sass maps, generation and artifact linking.** Extract !default settings, maps, imports and generator inputs. Link published CSS/JS artifacts to definitions; treat compile-dependent values as unresolved until a controlled build is supplied. Evidence: [GOV.UK Frontend](#govuk) (tokens), [Carbon](#carbon) (tokens), [Material Web](#material) (tokens), [Elastic EUI](#eui) (tokens).

5. **React component records and variant adapters.** Discover package exports and TS/TSX modules; capture props, defaults, slots, polymorphism, controlled state, refs and style dependencies. Implement union/class-map, cva, prop-definition and recipe adapters without claiming visual equivalence from matching names. Evidence: [Primer React](#primer) (variants), [Fluent UI React v9](#fluent) (variants), [Chakra UI](#chakra) (variants), [Radix Themes](#radix) (variants), [shadcn/ui registry](#shadcn) (variants), [Base UI](#baseui) (variants).

6. **Stories, docs and preview composition.** Parse Storybook CSF args/decorators, MDX and component doc metadata first, then custom TSX examples and registry entries. Missing stories require a preview recipe or consumer fixture; a docs page is not automatically a runnable isolated story. Evidence: [Primer React](#primer) (stories), [Fluent UI React v9](#fluent) (stories), [Gestalt](#gestalt) (stories), [shadcn/ui registry](#shadcn) (stories), [Documenso](#documenso) (stories).

7. **Runtime styling resolution and non-React targets.** Keep Emotion/Griffel providers, caches, transforms and generated CSS as explicit preview dependencies. Extend the record for Nunjucks macro schemas and Lit custom-element metadata after the React path works on real product repos. Evidence: [Chakra UI](#chakra) (styling), [Fluent UI React v9](#fluent) (styling), [Elastic EUI](#eui) (styling), [GOV.UK Frontend](#govuk) (variants), [Material Web](#material) (variants).

Discovery should produce source records before trying to rebuild a foreign system. Importing an existing component means preserving and previewing it with its dependencies; automatic conversion into Area’s semantic schema remains a separate migration step. This is a proposed boundary, not a capability already implemented by this survey.

## Hard cases

### Generated and separately versioned tokens

Source token formats, dependency versions and emitted CSS must remain distinct. Primer’s supporting source is pinned independently; Spectrum imports external token JSON; Carbon and Atlassian generate artifacts.

Evidence: [Primer React](#primer) (tokens), [React Spectrum / React Aria](#spectrum) (tokens), [Carbon](#carbon) (tokens), [Atlassian public packages](#atlassian) (tokens).

### Vendor mode extensions

A DTCG-looking file can store mode values in custom extensions, while JS themes can compute them. A schema label alone is insufficient to resolve every token.

Evidence: [Carbon](#carbon) (tokens), [Chakra UI](#chakra) (tokens), [Ant Design](#antd) (tokens).

### Runtime and compiled CSS-in-JS

Style functions can depend on theme, props and runtime state; build-time extraction/macro transforms require the original toolchain. Record opaque dependencies before attempting normalization.

Evidence: [Fluent UI React v9](#fluent) (styling), [Atlassian public packages](#atlassian) (styling), [React Spectrum / React Aria](#spectrum) (styling), [Chakra UI](#chakra) (styling), [Elastic EUI](#eui) (styling).

### Scope and cascade

Nested providers, classes, data attributes, media conditions and scale parameters change resolution. Preserve these conditions and source order rather than deduplicating equal variable names.

Evidence: [Primer React](#primer) (themes), [Radix Themes](#radix) (themes), [Mantine](#mantine) (themes).

### Unstyled behavior packages

Base UI and React Aria can supply behavior without a prescribed visual token set. Documentation themes must not be mistaken for required library tokens.

Evidence: [Base UI](#baseui) (styling), [React Spectrum / React Aria](#spectrum) (styling).

### Registry source and product drift

A source registry contains bases/styles/dependency metadata; products own local copies that may acquire wrappers, new variants and different theme initialization.

Evidence: [shadcn/ui registry](#shadcn) (variants), [OpenStatus](#openstatus) (variants), [Documenso](#documenso) (variants), [Midday](#midday) (variants).

### Preview formats are heterogeneous

CSF is only one input. TSX docs/examples, route-based playgrounds, YAML fixtures and Lit stories need adapters; the three product clones have no conventional Storybook paths.

Evidence: [Fluent UI React v9](#fluent) (stories), [Gestalt](#gestalt) (stories), [Radix Themes](#radix) (stories), [GOV.UK Frontend](#govuk) (stories), [Material Web](#material) (stories), [OpenStatus](#openstatus) (stories), [Documenso](#documenso) (stories), [Midday](#midday) (stories).

### Counts and compound components

Public module, documented family, registry item and custom-element tag counts differ. Keep the explicit counting scope and full member paths; do not compare totals as interchangeable library sizes.

Evidence: [Primer React](#primer) (scope), [Fluent UI React v9](#fluent) (scope), [Material Web](#material) (scope).

### License granularity

Repository roots, individual files, vendored UI and enterprise packages can have different terms. Preserve declarations at their actual scope; this survey does not determine reuse permissions.

Evidence: [Elastic EUI](#eui) (license), [Documenso](#documenso) (license), [Midday](#midday) (license).
