1 · Fix first · done

Defects that need no taste call. You chose to fix all of them, and every item here is fixed in PR 28. The specimens show the state before the fix. The full list, with filters, is in section 4.

A-1 · A-2

Button group: the outline border breaks on hover, and a default Button reads white on grey

HighFixed · PR 28

The group sets the border but not --_border-hover, so a ghost child's transparent hover edge wins. The group repaints a child's fill but not its ink, so an unmodified <Button> keeps its solid white label. Every demo passes variant="ghost", which hides it.

D-4

Tree view: a selected row loses its plate under the pointer

HighFixed · PR 28

The hover rule excludes aria-current rows but not aria-selected ones, and it outranks the selection rule. In the Layers tile, the selected row drops from #ee to #f3 when hovered. The cohesion test only checks that each rule's colour is right, so it passes anyway.

G-3

Code block rules vanish in dark

HighFixed · PR 28

bg-code, bg-stripe, bg-subtle and border-decorative all resolve to #282828 in dark, so the header, toggle and flush rules match the fill. Dark isn't reviewed yet, but this one is a token collision rather than a taste call.

E-9

Reduced motion turns indeterminate Progress into "35% done"

MediumFixed · PR 28

The indeterminate bar is a 35%-wide segment. With motion off it stops at the inline start, which looks exactly like value={35}. Spinner slows down under reduced motion instead of stopping.

H-1 · H-3 · F-5

Radius and Surface presets break shapes and required edges

HighFixed · PR 28

Under Pill, any uncapped radius-control-* shape becomes a capsule: Card, the colour area, the alignment grid, Kbd, Calendar days, the banner. Under Elevated (border-width: 0), required edges disappear: an outline Button looks ghost, a checked choice card loses its edge, a white swatch disappears. Required edges should use stroke-width. The Card corner itself is a decision (S3).

C-8 · F-9 · E-4 · G-11

Four behaviour bugs with the widest reach

HighFixed · PR 28

RadioGroup never generates a name. Without one it isn't a native group: arrows don't move the selection, every radio is a Tab stop, and nothing submits. Calendar traps focus in front of an unavailable date, because disabled days are native disabled buttons. Escape on a tooltip also closes the Popover or Dialog it sits in. Model picker hand-builds its menu button: CSS-anchor-only placement, no arrow-key open, no close on Tab.

Fixed: RadioGroup generates a name, unavailable days stay focusable with aria-disabled, Escape closes only the tooltip, and Model picker uses Menu's trigger path.

2 · System rules to settle

Each card settles a rule that several families disagree on. The specimens show the current state beside each option.

S1

Field focus is barely visible

HighB-1 · a11y{{status:S1}}

At standard contrast, a focused field's edge is the hover grey (#d4, about 1.5:1 on white) plus a 2px halo of 6% black. In dark mode the rest, hover and focus edges are all the same rung. Buttons, Checkboxes and InputAction in the same form use the 2px focus ring. Notion draws a 2px blue ring on fields, and ChatGPT a 1px blue edge. Verified live: the field focus colour mixes in the focus hue at 0%.

{{choose:S1}}

Recommended B: both products colour the focus edge, the design system says focus is a system role rather than an accent choice, and it fixes dark mode. D is the minimum.

S2

Where 500 applies: surface titles and labels

HighE-1 · F-8 · D-1 · H-6 · A-21 · C-3{{status:S2}}

DESIGN_SYSTEM.md says 400 for text and every title, and 500 only for labels on fills. In the approved code, 500 is used on the titles of Popover, Dialog, Toast, Alert, Card, Panel (bar and headings) and Calendar, and on Nav group titles; typography.md agrees with the code. Labels apply the rule four ways: solid Button only, every Badge (outline included), soft Count only, and every Segmented option on a transparent track.

S3

Card's corner rule ignores the radius presets

HighF-1 · H-1 · H-2 · E-14 · F-33{{status:S3}}

The owner's rule gives Card control-md + inset + step (22/24/28). It has no cap. Under Sharp the card stays rounded at 16, and under Pill the corner becomes 1015px, so the card turns into a stadium. Dialog uses the same idea with a cap, min(container × 2, …). The same leak affects Composer, Message and Toolbar under Sharp.

{{choose:S3}}

Recommended C (the system audit) or A (the surfaces audit). They look identical. C also fixes Sharp for Composer, Message, Toolbar and Segmented, and gives DESIGN_SYSTEM a written rule to replace "Card is twice the container radius".

{{choose:S3b}}
S4

Control corners: stepped by tier, or one value

MediumA-5 · B-17 · F-12{{status:S4}}

Button, Button group, Toolbar and Split button use radius-control-sm/md/lg (6/8/10). Input, Select, Textarea, NumberField, InputGroup and the Segmented track stay 8 at every size. Calendar's 32px days use 6. In a small form row or toolbar, the corners disagree by 2px.

S9

Close and dismiss are built five ways

MediumC-4 · E-2 · E-3 · G-18 · H-11{{status:S9}}

Popover and Toast use a ghost small Button (28, radius 6, Area glyph, #56 ink). Dialog uses a medium Button (32, radius 8). Alert builds its own button: full ink, a Fluent filled glyph, and a 12%-ink hover plate that is much darker on the neutral grey. Chip uses a muted circle with a Fluent glyph; Badge a 12–16px circle with an Area glyph. The rule says "28px, small-button radius". The API names are onDismiss, onRemove and onClose.

S11

List rows: label column, keyboard focus and nested hover

MediumD-2 · D-7 · D-6{{status:S11}}

All list families read the same product evidence (labels at about 36 in ChatGPT and Notion). Menu, Palette and Combobox start icon-row labels at 36 (a literal 12 gap that ignores compact). Nav starts at 32 (8 gap), Tree at 52 (chevron, then a 6 gap), and Select options at 32. The offsets below are measured live.

{{choose:S11a}}

Keyboard focus on a row is shown four ways. Menu and Palette use the plate. Nav and Tree use a 2px ring 2px outside the row, which covers neighbouring rows 2px away. Tabs and Select use an inset ring. Breadcrumb's ring hugs the text while its plate is wider. Nested ghost Buttons and the Tree chevron also hover with the same #f3 as the row they sit on. They vanish on a hovered row and show as a lighter hole on a current row.

S13

How a selected row looks in menus and pickers

MediumD-9 · B-6{{status:S13}}

S21

Compact density, dark mode and the token phase

MediumH-4 · H-5 · H-9 · H-17{{status:S21}}

About 41% of dimension declarations (471 of 1,158) are fixed and won't compress in compact density. Mostly fixed: Badge, Nav, Tooltip, choice controls, Code block, Card, Calendar, Panel, Menu. Nearly all density-driven: Button, fields, Segmented, Chip. Dark rests on 26 literals that were never captured. The value clusters ready to become tokens with no visual change: the floating lift (×9), the scrim (×3), disabled opacity 0.5 (×16), the 16/20/24 mark ladder, and z-index (a token scale exists but isn't used). None of the 63 :hover rules sit inside @media (hover: hover).
