Working deep in a system or a design

Where it stands: the Sidebar is four places held at the top (Home, References, Projects, Systems), a rule, then what the tab holds, and that section's list, in one scroll. Below are real captures from the app with a test project: Button's variant tiles opened four levels down, and a page with 14 layers in a project with 6 pages and 3 explorations.

Fixes I'll make either way

  • The selected row is always in view.Whenever a tab or a page opens, the list scrolls to its selected row (layer 9, outline-success). Today the Sidebar's "start at the top" rule overrides the list's own reveal.
  • A screen added twice gets a number."Analytics dashboard 2", as New page and New exploration already number theirs.

Round 1

What happens today

Each tab swaps the whole Sidebar for its own nav under a “← Home” row. Home's tab lists the workspace; References' tab lists only its views; a system's tab lists only that system; a project's tab lists only that project. Four navs share one place, and the way back is a row whose meaning changes.

What Cursor and Claude do

Read from the installed apps' own code (Claude desktop 4.4212.0, Cursor 3.27.22). Full notes with file names: docs/research/consistent-nav-2026-11-01/README.md.

  • Claude keeps one frame and changes only a slot's words.Chat, Cowork and Code are surfaces of one window (⌘ keys step between them). Every slot stays put: New, Search, the list, the person and Settings. Its code declares each slot's words in pairs, “New chat” or “New Code session”, “All chats” or “Recents”, “Search conversations and projects” or “Search sessions and projects”.
  • Cursor lists every workspace's agents at once, grouped.The Agents window's one list groups by Workspace, Repository, Updated, Status or Environment. Each group folds and shows 5 rows, then “Show more”. New Agent and Search sit above it, Settings at the foot.
  • Cursor's IDE never moves its activity bar.Its explorer shows each folder of a workspace as a top-level disclosure and reveals the current file in place, opened and marked.
  • Linear and Notion (from use, not measured)keep fixed rows on top (Inbox, Home, Search), then every team or teamspace as a disclosure of the same sections.

They agree on five things: persistent rows never move; everything is listed at once, grouped by its parent; the current thing is revealed where it lives, not swapped in; the tree stays two or three levels deep, with long contents in a view of their own; and the section names are the same under every item.

Recommendation

Direction A, one tree. It is what you picked, and it is what Linear, Notion and Cursor's explorer do. Home and References stay at the top of every tab. Every project and system is in one list with its sections under it, and the current tab's item opens where it lives. The Sidebar never changes shape, and nothing replaces it. B adds a second set of tabs beside the Canvas's own. C keeps everything listed, but its block of sections changes owner each time you switch tabs, which is the swap you asked to remove, on a smaller scale.

What A costs: the tree gets long with many items open, so other items stay as you left them and each group shows 5 items, then “Show more” (Cursor's rule). Components' families move to the list under the nav, where Colors' scales and Icons' categories already are, so the tree stays three levels deep.
